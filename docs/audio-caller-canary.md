# Automated audio caller: bounded batch

The runner implements the user's **ceiling of six automated call attempts including failures and retries**, one at a time. The original canary failed before a CallSid (HTTP 401/code 20003) and remains one consumed fixture attempt. A separate non-dialing diagnostic identified an unapproved Primary Compliance Profile; this is the observed cause for this account, not a universal interpretation of code 20003. The route and synthetic audio exchange remain unproved. No provider call was made while implementing the batch extension. The test dials only the configured owned FirstRing number through the existing authenticated Photon SIP adapter; `TEST_CALLS_AUTHORIZED`, `HANDOFF_CALLS_ENABLED`, and `FAMILY_CALLS_ENABLED` remain false. It does not consume the Sarah probe reservation or dial an enrolled contact.

The operator authenticates with the existing Bearer token. `GET /api/demo/audio-fixture` is read-only. The legacy `POST /api/demo/audio-fixture` body `{"scenario_id":"clinic_to_login_george"}` remains idempotent to the original canary. A new attempt requires exactly `scenario_id` plus an operator-generated UUID `request_id`; no target, URL or other override is accepted. Available scripts are `clinic_to_login_george`, `routine_message_george`, `ambiguous_to_login_george`, `ambiguous_to_reference_george`, `explicit_login_george`, `negated_warning_george`, `supplied_reference_george`, `quoted_report_george` and `handoff_changed_george`. Each plays at most two cached clips. Noise mixing and intentional interruption are explicitly unsupported. It reserves a durable `fixture_caller` action before submission and returns the reservation; request accepted is not ringing, answer, or success. Repeating a request ID returns its same run and never retries. An atomic ledger guard counts every live fixture reservation, caps the total at six, requires every earlier caller to be known terminal and every correlated defender to have a terminal provider receipt, and stops after a loop or two consecutive infrastructure failures. A completed caller without a correlated defender also requires reconciliation. No script starts the next call automatically. Unknown create results require reconciliation. A crash keeps the attempt consumed. Numeric Twilio API error codes are retained without raw provider error bodies.

The caller first gathers Sarah's greeting, then plays each selected cached George clip and gathers her reply. The original canary uses the clinic opening followed by the login request. These are existing ElevenLabs recordings; no synthesis or ElevenLabs agent is invoked. Empty speech stops the sequence. Signed callbacks bind the action, caller CallSid and sequential step; duplicates return the cached response. Final `SpeechResult` and explicitly unstable partial observations are separate. Partial results never advance the script. `audio_exchange_captured_ungraded` is an evidence state, not a behavioral pass.

The media route serves only the two selected hash-verified MP3s behind a random capability expiring after five minutes. Neither the capability nor the provider recording URL is exposed by the status API. The synthetic call requests dual-channel recording. A signed recording receipt must match the reserved caller leg; `GET /api/demo/audio-fixture/recording?action_id=ACTION_ID` retrieves its MP3 through authenticated server-side provider access. Recordings remain pending until the provider's completed receipt; no recording is claimed merely because it was requested.

The caller has a provider limit of at most 90 seconds. A signed inbound request from the owned origin while this single reservation is pending binds the defender leg; this is narrow test correlation, not caller-ID identity verification. The defender receives a provider 90-second duration update and a local actor cancellation deadline. A second distinct matching inbound leg triggers loop shutdown. `POST /api/demo/audio-fixture/stop?action_id=ACTION_ID` requests cleanup of both known legs; omitting the action ID selects the current run. State, recordings and callbacks remain associated with their original action; old callbacks cannot advance the current run. The original singleton metadata and reservation are preserved. GET state includes attempt counts, history and supported scenarios; terminal provider callbacks establish actual completion. If origin correlation or the provider duration update fails, the operator must supervise cleanup using the existing call controls. No automatic route change or redial occurs.

Photon documents using its eligible number as the SIP caller identity, but does not promise calling that same DID will route back successfully. The self-call remains experimental. Read-only Twilio account checks found no existing outgoing caller IDs and no Twilio numbers, so direct PSTN is not currently a setup-free fallback. Stop and retain the result if self-routing fails; do not purchase or verify a number automatically.

Successful audio playback, defender Relay transcripts, real Nemotron tool receipts, caller-side audio recognition and the recording must be correlated before grading the exchange. This digital path is not a noisy-room or human voice-quality test. No background noise is mixed into the canary.
