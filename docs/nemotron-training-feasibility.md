# Exact Lightning LoRA feasibility

Status, 2026-11-08: **zero optimizer steps run; no trained adapter or training improvement claimed.** A valid native-tool baseline remains the first gate. The authorized campaign now ends work at **09:09:50 UTC**, with cleanup by **09:39:50 UTC** on the existing H100; this does not establish a training duration or authorize another allocation.

- **Correct base:** train `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`, preserving the Lightning model. NVIDIA explicitly says AutoModel cannot dequantize the ModelOpt NVFP4 inference checkpoint. Its documented Lightning LoRA profile uses **4 × 80 GB GPUs**; this is a reference configuration, not a proven minimum. [NVIDIA training requirements](https://docs.nvidia.com/nemo-helix/documentation/customizer-reference/models/llama-nemotron/)
- **Single-GPU evidence:** NVIDIA publishes an exact Lightning rank-8 LoRA recipe using **one B300**, NeMo AutoModel `26.08`, and exclusion of `*.out_proj` because the Mamba kernel accesses those weights directly. It is not a demonstrated H100 result. The recipe recommends about 200 GB storage. [Official recipe](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/usage-cookbook/Nemotron-3.5-Lightning/dgx-station-recipes/lora.md)
- **Memory:** the BF16 index at revision `28ae02f54748b2784572c929585adff2d0d62130` reports **65,842,365,568 bytes (61.32 GiB)** across 14 shards. This is tensor storage, not total training VRAM. Activations, adapter gradients/optimizer state, kernels and temporary allocations need additional space. Short sequences and batch one might fit a single H100, but that remains an unmeasured hypothesis. The serving process must release its GPU allocation before a training test. [Exact index](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16/blob/28ae02f54748b2784572c929585adff2d0d62130/model.safetensors.index.json)
- **Export/runtime:** NeMo AutoModel is NVIDIA's supported tooling, not an unrelated dependency. Its PEFT output is adapter weights plus configuration. Grouped-expert PEFT-v5 merges require `--automodel-native-export`; merged BF16 output needs substantial additional storage. vLLM **0.27.1** supports NemotronH LoRA but explicitly skips `mtp.*` adapters. This does not prove that the cookbook adapter layout loads directly on our NVFP4 runtime. Verify base revision, target modules, adapter format, load and native-tool behavior before selecting it. [AutoModel export](https://docs.nvidia.com/nemo/automodel/latest/recipes-e2e-examples/sft-peft), [pinned vLLM implementation](https://github.com/vllm-project/vllm/blob/v0.27.1/vllm/model_executor/models/nemotron_h.py)
