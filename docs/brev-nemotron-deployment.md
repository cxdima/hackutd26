## Pinned serving recipe

Use the official [Nemotron 3.5 Lightning vLLM cookbook](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/usage-cookbook/Nemotron-3.5-Lightning/vllm_cookbook.ipynb), one H100 80GB, **NVFP4**, without the optional speculative draft checkpoint. The model has approximately 30B total parameters; 3B active parameters do not determine checkpoint memory. The public checkpoint metadata contains **52 safetensors files / 21,561,882,284 bytes**, before runtime, KV/state cache and kernel memory. A 22GB L4 is not this verified profile.

`scripts/brev-nemotron/deployment.json` records the immutable model revision and verified vLLM image index digest. `serve.sh` uses cookbook vLLM **v0.27.1**, `qwen3_coder` native tool parsing, `nemotron_v3` reasoning parsing, automatic tool choice and the checkpoint's own chat template. It reduces context to 8,192 and concurrency to four for this demo. Requests should set `chat_template_kwargs.enable_thinking=false`. The newer NVIDIA voice-agent blueprint uses v0.31.0 with different kernel flags; those recipes have not been mixed.

No NVIDIA workload key is needed to download this ungated Hugging Face checkpoint or public image. The instance creates a separate inference key in a mode-0600 private file. Port 8000 binds only to the GPU host's loopback; use Brev SSH forwarding to local port **18080**. A browser-authenticated Brev console URL is not a Rust inference endpoint. The app must identify this backend as self-hosted NVFP4 with its checkpoint revision, even though the served model alias stays compatible.
